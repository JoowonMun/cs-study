## 파트 1. Python 코드가 실행되는 과정

### 1-1. 컴파일 언어와 인터프리터 언어

컴퓨터의 CPU는 `0`과 `1`로 된 **기계어**만 이해한다. 사람이 쓴 코드를 기계어로 바꾸는 방식은 크게 두 가지다.

| | 컴파일 언어 | 인터프리터 언어 |
|---|---|---|
| 방식 | 실행 **전에** 전체를 기계어로 번역해 실행 파일을 만든다 | 실행하면서 번역해 바로 실행한다 |
| 비유 | 책 한 권을 미리 **번역 출판** | 옆에서 **동시통역** |
| 장점 | 실행이 빠르다 | 바로 실행해 보고 고치기 편하다 |
| 예 | C, C++, Go, Rust | Python, R, JavaScript |

R 콘솔에 코드를 치면 바로 결과가 나오던 것도 인터프리터 방식이기 때문이다.

### 1-2. Python의 실제 실행 과정

사실 Python은 순수한 동시통역이 아니라, **중간 단계를 한 번 거친다.**

```
 hello.py  ──컴파일──▶  바이트코드  ──실행──▶  Python 가상 머신(PVM)  ──▶  결과
 (소스 코드)            (.pyc)                  (바이트코드를 한 줄씩 해석)
```

1. **컴파일:** 소스 코드를 **바이트코드(bytecode)**라는 중간 언어로 번역한다. 기계어는 아니고, Python 가상 머신이 이해하는 명령어다.
2. **실행:** **Python 가상 머신(PVM, Python Virtual Machine)**이 바이트코드를 한 줄씩 해석해 실행한다.

우리가 설치한 Python의 정식 이름은 **CPython**이다. C 언어로 만든 Python 인터프리터라는 뜻이다. 보통 "Python"이라고 하면 이것을 말한다.

- 다른 파일에서 `import`한 모듈의 바이트코드는 **`__pycache__/` 폴더에 `.pyc` 파일로 저장**해 둔다. 다음에 실행할 때 소스가 바뀌지 않았으면 컴파일을 건너뛰어 더 빨리 시작한다.
- `.gitignore`에 `__pycache__/`가 들어 있는 이유가 이것이다. 소스만 있으면 언제든 다시 만들어지는 파일이다.
- 03단계에서 배울 Java도 **바이트코드 + 가상 머신(JVM)** 구조다. Python과 비교해 보면 재미있다.

### 1-3. 실행하는 세 가지 방법

| 방법 | 명령 | 특징 |
|---|---|---|
| **REPL** | `uv run python` | 한 줄씩 입력하고 바로 결과를 본다. 마지막 식의 값을 **자동으로 출력**한다. 빠른 실험용 |
| **스크립트** | `uv run python 파일.py` | 파일 전체를 위에서 아래로 실행한다. `print()`한 것만 출력된다. 실제 프로그램은 이 방식 |
| **Jupyter** | 노트북의 셀 실행 | REPL을 셀 단위로 묶은 것. 셀 마지막 식의 값을 자동 출력한다 |

> **REPL**은 Read(읽고) - Eval(평가하고) - Print(출력하고) - Loop(반복)의 줄임말이다. 프롬프트 `>>>`가 보이면 REPL 안에 있는 것이다. `exit()`로 빠져나온다.

⚠️ **Jupyter의 함정:** 셀은 위에서 아래가 아니라 **실행한 순서대로** 상태가 쌓인다. 셀 3을 고치고 셀 2를 다시 돌리면, 노트북은 위에서 아래로 실행했을 때와 다른 상태가 된다. "내 노트북에서는 됐는데 처음부터 다시 돌리면 에러"가 나는 이유다. 실제 서비스 코드를 스크립트로 쓰는 이유 중 하나다.

## 파트 2. Python에서는 모든 것이 객체다

Python에서 숫자, 문자열, 리스트, 함수, 심지어 `None`까지 **모든 값은 객체(object)**다. 객체는 세 가지 속성을 가진다.

| 속성 | 뜻 | 확인 방법 | 바뀌는가 |
|---|---|---|---|
| **정체성 (identity)** | 메모리 어디에 있는 객체인가 | `id(객체)` | 객체가 살아 있는 동안 안 바뀜 |
| **타입 (type)** | 무슨 종류의 객체인가 | `type(객체)` | 안 바뀜 |
| **값 (value)** | 담고 있는 내용 | 객체 자체 | 객체에 따라 다름 (s02에서 다룸) |

```python
>>> type(3)
<class 'int'>
>>> type("a")
<class 'str'>
>>> type(print)
<class 'builtin_function_or_method'>
>>> id(3)
140715183290120      # 프로그램을 새로 실행할 때마다 다른 숫자가 나온다
```

> **"안 바뀐다"는 건 언제까지?** 객체가 **살아 있는 동안**이다. 호텔 방 번호와 비슷하다.
> - 투숙하는 동안(프로그램이 실행되는 동안) 내 방 번호는 바뀌지 않는다.
> - 체크아웃하면(프로그램 종료) 방은 비워진다. 다음 여행(다시 실행)에서는 그때 비어 있는 방을 새로 배정받으니 번호가 달라진다.
> - 체크아웃한 방은 다른 손님이 쓸 수 있듯이, 사라진 객체의 `id`는 나중에 다른 객체가 물려받을 수도 있다.

`id()`는 객체의 **고유 번호**다. CPython에서는 객체가 있는 메모리 주소다. 02단계(C 언어)에서 메모리 주소를 직접 다루게 된다.

## 파트 3. 변수는 상자가 아니라 이름표다

### 3-1. 두 가지 모델

변수를 **상자**로 생각하는 사람이 많다. "`a`라는 상자에 값을 넣는다." C 언어에서는 이 모델이 맞다. 하지만 **Python에서는 틀린 모델이다.**

Python의 변수는 **객체에 붙이는 이름표(name tag)**다. `=`(대입)은 값을 복사해서 넣는 게 아니라, **오른쪽 객체에 왼쪽 이름표를 붙이는 것**이다.

```python
a = [1, 2]
b = a
```

```
 상자 모델 (틀림)                이름표 모델 (맞음)

  a: [1, 2]                     a ──┐
  b: [1, 2]  ← 복사본               ├──▶  [1, 2]   (리스트 객체 하나)
                                b ──┘
```

`b = a`는 리스트를 복사하지 않는다. **같은 리스트 객체에 이름표를 하나 더 붙였을 뿐이다.** 그래서 `b`로 리스트를 바꾸면 `a`로 봐도 바뀌어 있다.

```python
>>> b.append(3)
>>> a
[1, 2, 3]
>>> a is b
True
```

### 3-2. 익숙한 함정: pandas

분석하다가 이런 경험이 있을 것이다.

```python
df2 = df            # 복사했다고 생각했지만
df2["score"] = 0    # df2를 고쳤는데
df                  # 원본 df도 score가 전부 0이 되어 있다
```

`df2 = df`도 같은 DataFrame 객체에 이름표를 하나 더 붙인 것이기 때문이다. 원본을 지키려면 **`df2 = df.copy()`**로 새 객체를 만들어야 한다. 리스트도 마찬가지로 `a.copy()`나 `list(a)`로 복사한다.

### 3-3. 그런데 숫자는 왜 괜찮을까

```python
>>> n = 10
>>> m = n
>>> m += 1
>>> n
10
```

`m = n` 직후에는 `n`과 `m`이 같은 `10` 객체에 붙어 있다. 그런데 `m += 1`은 `10` 객체를 바꾸는 게 아니라, **새 객체 `11`을 만들고 `m` 이름표를 그쪽으로 옮겨 붙인다.**

```
 m = n 직후            m += 1 직후

 n ──┐                 n ──▶ 10
     ├──▶ 10
 m ──┘                 m ──▶ 11  (새 객체)
```

숫자 객체는 한번 만들어지면 내용을 바꿀 수 없기 때문이다. 이런 객체를 **불변(immutable) 객체**라고 하고, 리스트처럼 내용을 바꿀 수 있는 객체를 **가변(mutable) 객체**라고 한다. s02에서 자세히 다룬다. 오늘은 **"리스트는 내용을 바꾸고, 숫자는 이름표를 옮긴다"** 정도로 기억한다.

### 실습 2. 이름표 추적하기 (REPL)


- `b = [9, 9]`는 새 리스트 객체를 만들고 **`b` 이름표만 옮겨 붙인다.** `a`가 가리키는 객체는 건드리지 않는다.

**"객체를 바꾸는 것"과 "이름표를 옮기는 것"을 구분하는 것**이 오늘의 핵심이다.

</details>

## 파트 4. `is`와 `==`

### 4-1. 차이

| 연산자 | 묻는 것 | 비유 |
|---|---|---|
| `==` | **값**이 같은가? | 두 사람이 같은 옷을 입었는가 |
| `is` | **같은 객체**인가? (`id`가 같은가) | 두 이름이 같은 사람을 가리키는가 |

```python
>>> c = [1, 2, 3]
>>> d = [1, 2, 3]
>>> c == d      # 내용이 같다
True
>>> c is d      # 하지만 따로 만든 두 객체다
False
```

### 4-2. 규칙: `is`는 `None`에만 쓴다

값을 비교할 때는 항상 `==`를 쓴다. `is`는 **`x is None`처럼 `None`을 확인할 때만** 쓴다. `None`은 프로그램 전체에 딱 하나만 존재하는 객체라서 `is`로 비교하는 게 정확하고 빠르다.

숫자나 문자열에 `is`를 쓰면 안 되는 이유는, **결과가 상황에 따라 달라지기** 때문이다. CPython은 메모리를 아끼려고 내부적으로 객체를 재사용한다.

- `-5`부터 `256`까지의 작은 정수는 미리 만들어 두고 계속 재사용한다.
- 짧은 문자열도 재사용하는 경우가 많다.
- 같은 파일 안에 같은 상수가 여러 번 나오면 하나로 합치기도 한다.

이건 CPython 내부의 최적화일 뿐, 언어가 보장하는 동작이 아니다. 실습 3에서 직접 확인한다.

### 실습 3. `is`가 믿을 수 없는 이유

**1) REPL에서** 한 줄씩 입력한다.

```python

y = 256
x is y
a = 1000
b = 1000
a is b
a == b
```

**2) 스크립트에서** `01-python/labs/s01_is.py`를 만들어 같은 내용을 실행한다.



**Q1.** REPL에서 `256`은 `is`가 `True`였는데 `1000`은 `False`였다. 왜 그런가?
<details>
<summary>정답 보기</summary>

`-5`~`256`의 작은 정수는 CPython이 미리 만들어 두고 재사용하므로 `x`와 `y`가 같은 객체를 가리킨다. `1000`은 그 범위 밖이라, REPL에서 줄마다 따로 실행하면 각각 새 객체가 만들어진다.

</details>

<br>

**Q2.** 같은 `a = 1000; b = 1000`인데 스크립트에서는 `a is b`가 `True`였다. 왜 그런가?
<details>
<summary>정답 보기</summary>

스크립트는 파일 전체를 한 번에 컴파일한다. 컴파일러가 같은 파일 안에 똑같은 상수 `1000`이 두 번 나오는 것을 보고 객체 하나로 합쳤기 때문이다. REPL은 한 줄씩 따로 컴파일하므로 이 합치기가 일어나지 않는다.

**같은 코드인데 실행 방법에 따라 `is`의 결과가 달라진다.** 그래서 값 비교에 `is`를 쓰면 안 된다.

</details>

<br>

**Q3.** `print(a is 1000)` 줄에서 결과 외에 어떤 메시지가 나왔는가?
<details>
<summary>정답 보기</summary>

`SyntaxWarning: "is" with 'int' literal. Did you mean "=="?` Python도 이 실수가 흔하다는 걸 알아서 경고해 준다.

</details>

## 실습 4. 출력 예측 (손으로 먼저)

**실행하지 말고** 종이에 이름표 그림을 그려 출력을 예측한다. 다 예측한 뒤에 정답을 연다. (정보처리기사 실기에도 이런 "코드 출력 예측" 문제가 나온다)

**Q1.**

```python
x = [10, 20]
y = x
z = [10, 20]
y.append(30)
print(x)
print(x == z, x is z, x is y)
```
<details>
<summary>정답 보기</summary>

```
[10, 20, 30]
False False True
```

`y`와 `x`는 같은 객체라 `y.append(30)`이 `x`에도 보인다. `z`는 처음부터 따로 만든 객체이고, 이제 값도 `[10, 20]`이라 `x`와 다르다.

</details>

**Q2.**

```python
p = [1, 2]

print(q)
```
<details>
<summary>정답 보기</summary>

```
[1, 2, 3]
[1, 2]
```

`p + [3]`은 기존 리스트를 바꾸지 않고 **새 리스트를 만든다.** 그 새 객체에 `p` 이름표를 옮겨 붙였으므로, `q`는 원래 리스트 `[1, 2]`를 그대로 가리킨다. (`p.append(3)`이었다면 둘 다 `[1, 2, 3]`이 됐을 것이다)

</details>

```python
print(s, t)
```
<details>
<summary>정답 보기</summary>

```
hi hi!
```

문자열도 숫자처럼 **불변** 객체다. `t + "!"`는 새 문자열을 만들고 `t` 이름표를 옮겨 붙인다. `s`는 그대로다.

## 실습 5. 직접 짜기: 원본 지키기

`01-python/labs/s01_backup.py`를 **처음부터 직접** 작성한다.

**요구사항**

1. `scores = [80, 90]` 리스트를 만든다.
2. `alias = scores`로 이름표를 하나 더 붙이고, `alias`에 `100`을 추가한다.
3. `scores`가 바뀌었다는 것을 출력으로 보여준다. 두 이름이 **같은 객체**라는 것도 `is`로 보여준다.
4. 이번에는 `scores`의 **복사본** `backup`을 만든다. (방법은 파트 3-2에 있다)
5. `backup`에 `70`을 추가해도 `scores`는 바뀌지 않는다는 것을 출력으로 보여준다.
6. 복사 직후 `backup == scores`는 `True`, `backup is scores`는 `False`라는 것을 보여준다. (5번보다 먼저 확인해야 한다)

**실행 결과 예시** (형식은 자유롭게 바꿔도 된다)

```
alias에 100 추가 후 scores: [80, 90, 100]
scores is alias: True
복사 직후 == : True
복사 직후 is : False
backup에 70 추가 후 scores: [80, 90, 100]
backup에 70 추가 후 backup: [80, 90, 100, 70]
```

```bash
uv run python 01-python/labs/s01_backup.py
```

막히면 아래 힌트를 **하나씩만** 연다.

<details>
<summary>힌트 1: 방향</summary>

위에서 아래로 요구사항 순서대로 한 줄씩 쓰면 된다. 각 단계 뒤에 `print()`로 상태를 찍는다.

</details>

<details>
<summary>힌트 2: 쓸 도구</summary>

- 리스트에 값 추가: `리스트.append(값)`
- 복사본 만들기: `리스트.copy()`
- 문자열과 값을 함께 출력: `print("설명:", 값)`

</details>

<details>
<summary>힌트 3: 순서</summary>

```
scores 만들기
alias = scores
alias에 100 추가
scores 출력, scores is alias 출력
backup = scores의 복사본
backup == scores 출력, backup is scores 출력
backup에 70 추가
scores 출력, backup 출력
```

</details>

**Q1.** Python 코드가 실행되는 과정을 "바이트코드"와 "가상 머신"이라는 단어를 넣어 설명하라.
<details>
<summary>정답 보기</summary>

소스 코드를 먼저 **바이트코드**로 컴파일하고, **Python 가상 머신(PVM)**이 그 바이트코드를 한 줄씩 해석해 실행한다.

</details>

<br>

**Q2.** 다음 코드의 출력은?

```python
a = [1, 2, 3]
b = a
b[0] = 100
print(a[0])
```
<details>
<summary>정답 보기</summary>

`100`. `b[0] = 100`은 `b`가 가리키는 **리스트 객체 자체를** 바꾼다. `a`도 같은 객체를 가리킨다.

</details>

<br>

**Q3.** 다음 코드의 출력은?

```python
a = [1, 2, 3]
b = a
b = [100, 2, 3]
print(a[0])
```
<details>
<summary>정답 보기</summary>

`1`. `b = [100, 2, 3]`은 새 리스트에 `b` 이름표를 옮겨 붙였을 뿐, `a`의 객체는 그대로다.

</details>

<br>

**Q4.** `x == y`가 `True`인데 `x is y`가 `False`일 수 있는가? 반대로 `x is y`가 `True`인데 `x == y`가 `False`일 수 있는가?
<details>
<summary>정답 보기</summary>

- 앞의 경우는 흔하다. 내용이 같은 리스트를 따로 두 번 만들면 그렇다.
- 뒤의 경우는 일반적으로 없다. 같은 객체라면 값도 당연히 같다. (예외로 `float("nan")`은 자기 자신과도 `==`가 `False`다. 통계에서 `NaN != NaN`인 것과 같은 이유다)

</details>

<br>

**Q5.** 변수가 `None`인지 확인하는 올바른 코드는? `is`를 숫자 비교에 쓰면 안 되는 이유는?
<details>
<summary>정답 보기</summary>

`if x is None:`. 숫자나 문자열은 CPython의 내부 최적화(작은 정수 재사용, 상수 합치기)에 따라 `is`의 결과가 **실행 방법마다 달라질 수 있기** 때문이다. 값 비교는 항상 `==`로 한다.

</details>

<br>

**Q6.** pandas에서 `df2 = df` 후 `df2`를 고쳤더니 `df`도 바뀌었다. 이유와 해결 방법은?
<details>
<summary>정답 보기</summary>

`df2 = df`는 복사가 아니라 같은 DataFrame 객체에 이름표를 하나 더 붙인 것이다. `df2 = df.copy()`로 새 객체를 만들어야 한다.

</details>

<br>

**Q7.** `__pycache__` 폴더와 `.pyc` 파일은 무엇이고, Git에 올리지 않는 이유는?
<details>
<summary>정답 보기</summary>

import한 모듈의 **바이트코드를 저장해 둔 캐시**다. 다음 실행 때 컴파일을 건너뛰어 빨리 시작하려고 만든다. 소스 코드만 있으면 언제든 다시 만들어지고, Python 버전마다 내용이 달라서 Git에 올리지 않는다.

</details>
