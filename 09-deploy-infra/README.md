# 09. 배포와 인프라

내 컴퓨터에서만 돌아가는 코드를 다른 곳에서도 돌아가게 만드는 단계. 06~07에서 만든 API를 컨테이너로 묶고 자동화한다.

## 학습 목표

- Linux 환경에서 기본적인 서버 작업을 할 수 있다.
- Docker로 애플리케이션을 컨테이너화할 수 있다.
- 클라우드 서비스 모델의 차이를 설명할 수 있다.
- CI/CD로 테스트를 자동화하고, 로그로 문제를 추적할 수 있다.

## 세션 계획

| # | 주제 | 내용 |
|---|---|---|
| s01 | Linux 기초 | 파일 권한, 사용자, 프로세스 관리, 패키지 관리, SSH 개념 (WSL에서 실습) |
| s02 | 설정과 시크릿 | 환경변수, `.env`, 설정을 코드에서 분리하기, 시크릿 관리 |
| s03 | Docker ① | 컨테이너 vs 가상 머신, 이미지와 컨테이너, Dockerfile 작성 |
| s04 | Docker ② | 06~07 API 컨테이너화, docker compose로 API + DB 함께 띄우기 |
| s05 | 클라우드 기초 | IaaS/PaaS/SaaS, 컴퓨팅·스토리지·네트워크 서비스 개념 (특정 클라우드에 묶이지 않게) |
| s06 | CI/CD | GitHub Actions로 커밋할 때마다 테스트 자동 실행 |
| s07 | 로깅과 모니터링 | `logging` 모듈, 로그 레벨, 구조화된 로그, 모니터링 개념 |

## 체크리스트

- [ ] `chmod 755`의 의미를 설명할 수 있다
- [ ] 코드에 API 키를 직접 쓰면 안 되는 이유와 대안을 설명할 수 있다
- [ ] 내 API를 Docker 이미지로 만들어 실행했다
- [ ] docker compose로 여러 컨테이너를 함께 띄웠다
- [ ] GitHub Actions로 테스트가 자동으로 돌게 만들었다
- [ ] print 대신 logging을 쓰는 이유를 설명할 수 있다
