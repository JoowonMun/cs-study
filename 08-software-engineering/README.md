# 08. 소프트웨어 공학

"돌아가는 코드"에서 "함께 유지보수할 수 있는 코드"로 넘어가는 단계. 지금까지 짠 코드를 다시 보며 개선한다.

## 학습 목표

- 개발 방법론과 UML 다이어그램을 이해하고 그릴 수 있다.
- SOLID 원칙과 주요 디자인 패턴을 코드에 적용할 수 있다.
- 리팩터링, 테스트, 디버깅을 체계적으로 할 수 있다.
- Git으로 브랜치와 PR 기반 협업을 할 수 있다.

## 세션 계획

| # | 주제 | 내용 |
|---|---|---|
| s01 | 개발 방법론 | 소프트웨어 생명주기, 폭포수, 애자일, 스크럼 |
| s02 | 요구사항과 UML | 요구사항 분석, 유스케이스·클래스·시퀀스 다이어그램 |
| s03 | 설계 원칙 | SOLID, 응집도와 결합도 |
| s04 | 디자인 패턴 ① | 생성 패턴: 싱글턴, 팩토리 메서드, 빌더 |
| s05 | 디자인 패턴 ② | 구조·행위 패턴: 어댑터, 데코레이터, 전략, 옵서버 |
| s06 | 클린 코드와 리팩터링 | 이름 짓기, 함수 분리, 코드 냄새, 01~07 코드 하나를 골라 리팩터링 |
| s07 | 테스트와 디버깅 | 단위/통합 테스트, 블랙박스/화이트박스, 디버거 사용, 체계적인 디버깅 방법 |
| s08 | Git 협업 | 브랜치 전략, PR, 코드 리뷰, 충돌 해결, 형상 관리 |

## 체크리스트

- [ ] 결합도가 낮은 코드가 왜 좋은지 예를 들어 설명할 수 있다
- [ ] 디자인 패턴 3개 이상을 직접 코드로 구현했다
- [ ] 이전 단계의 코드를 리팩터링하고 전후를 비교했다
- [ ] VS Code 디버거로 브레이크포인트를 걸고 변수를 추적했다
- [ ] 브랜치를 만들어 PR을 올리고 머지해 봤다
